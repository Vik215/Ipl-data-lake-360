                 Business Analysis
				 
				 
				 
				 
				 
				 
I built an end-to-end IPL data engineering pipeline on AWS using Medallion Architecture. I used Amazon S3 as the data lake and divided it into Bronze, Silver, Gold and Error layers.


Raw IPL CSV files are first uploaded into the Bronze layer. An S3 event triggers a Python Lambda function, which validates the incoming file by checking the file type, required columns and record count. The Lambda also logs validation details to CloudWatch.


After validation, AWS Step Functions orchestrates the ETL workflow. I used Step Functions because it provides sequencing, retry and error-handling capabilities and allows independent Gold transformations to run in parallel.


The Bronze data is processed using AWS Glue PySpark. In the Silver transformation, I performed data-quality checks such as duplicate removal, null validation and schema checks. I also created derived business columns such as match year, month, winner flag, match status and winning-margin category. The transformed data is stored as Parquet in the Silver S3 layer.


I then used a Glue Crawler to discover the Parquet schema and populate the Glue Data Catalog. Amazon Athena uses this catalog metadata to query the Silver data directly from S3.


From the Silver layer, I created multiple Gold datasets using separate Glue jobs, including Team Wins, Season Summary, Venue Summary, Toss Analysis and Winning Margin Summary. These transformations are independent, so I designed them to run in parallel using Step Functions.


The Gold datasets are also stored in Parquet in S3, cataloged using Glue Crawler, and queried through Athena for business analysis.


So overall, the pipeline follows the flow: S3 Bronze → Lambda Validation → Step Functions → Glue Silver → Glue Catalog/Athena → Glue Gold → Glue Catalog/Athena
